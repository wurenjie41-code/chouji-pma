# WagerMemo 个人投注记录与风险管理路线图

## 当前版本盘点

当前公开版为纯 HTML/CSS/JavaScript PWA，代码位于 `pwa-v1/`，通过 GitHub Actions 发布到 GitHub Pages。已包含概览、逐注明细、历史分析、预算保护四页。存储使用同源 IndexedDB；口令经 PBKDF2 派生 AES-GCM 密钥，加密完整 JSON 状态；有最多 5 份本机快照和密文 JSON 导入/导出。2026-11-11 已交付本路线图 A 阶段，目标 iPhone 实机验收仍待用户操作。

现有 `records` 是独立的投注支出、派彩、退款、存款、提款流水，没有每注的赛事、赔率、结算状态、实际返还关联，也没有预算或风险设置。因此当前累计净结果不能区分已结算投注与未结算敞口，统计页也不能表示按不同字段分组的表现。当前版没有 OCR、图片附件、CSV 或修订历史。

## 增量原则

1. 继续保留纯本机、无账号密码、无远程赛事/赔率或投注服务的路线。
2. 先完成数据定义、迁移和保护逻辑，再扩展分析图表；禁止把旧的未关联流水猜成已结算投注。
3. 所有新增状态、图片与审计记录都进入加密 payload 与加密备份；默认不上传。
4. 预算、上限、暂停与冷静期是核心操作；历史分析只描述已有数据，不产生下注方向或加注建议。
5. 每个版本单独验收。保留当前网址和 IndexedDB 名称；改域名/路径前必须先验证密文导出/导入迁移。

## 数据模型建议：状态版本 2

向现有加密 payload 增加可选字段，解锁时先做幂等迁移；老字段不删除、不覆盖。成功提交新状态时写入新版本快照。导入旧备份时补齐空数组和默认设置。

```text
state v2
├── records[]            旧版原始流水，保留并标记 legacy / 结算关联未知
├── wagers[]             一注一条，可从 open 编辑到 settled/void/cashout
├── records[]            继续承担存取款、独立退款、奖金及资金移动，避免重复流水表
├── riskSettings         周期、预算、亏损上限、单笔上限、每日允许时段、冷静期、周期锁
└── auditLog[]           新增/编辑/删除的前后版本摘要，设置长度上限
```

投注字段：`id`、投注时间、事件/比赛、运动/类别、联赛、玩法、平台、赔率（定点整数）、投注金额（分）、单关/串关、状态、赛果、实际返还（含返还本金）、手续费、标签、备注、下注前状态、来源（manual/image）、创建/更新时间。未结算投注的返还与净结果为空；已结算投注按 `actualReturnMinor - stakeMinor - feeMinor` 计算。作废注须明确返还金额；不得同时把同一笔返还再记成独立流水。

现金流字段：类型、金额、发生时间、平台、备注、关联投注（可选）。存款、提款和奖金不计入投注 ROI。投注现金支出/结算返还由投注实体计算，不另造重复现金流行。展示的是根据已录记录推算的资金变化，不声称等于投注平台实时余额。

旧 `records[]` 始终保留原值。由于旧版没有结算状态或一一对应关系，旧投注事件只能显示为“旧版未关联流水”；默认从新口径的已结算 ROI 与未结算敞口中分离。旧版原始净结果可以单独展示，直到用户手动核对/重录。

## 统计口径默认值

- 默认周期为**本地法定月**；另提供周（周一至周日）和自定义日期范围。
- 日期维度开关：投注时间或结算时间。日/月按用户设备本地时区分组。
- 周期预算使用投注时间汇总已提交本金；赢款不返还预算额度，避免把赢钱额度误作可再投注额度。
- 已结算投注额和 ROI 默认只含有明确赛果的已结算投注；作废投注从 ROI 分母剔除，返还与手续费单列。
- ROI = 所选日期口径下已结算投注净结果 ÷ 已结算投注额。分母为零显示“—”。样本不足显示“数据不足”，不能评为优势或预测未来。
- 默认把结算样本少于 30 笔标为“样本较少”，降低图表强调程度；仍可查看原始数值，不生成稳定性结论。
- 未结算敞口 = 当前未结算投注本金总额。它单列显示；风险上限提醒可将该本金按全额风险计入预警，但明确这不是已发生亏损。
- 净存款 = 存款 − 提款；投注结果单独报告。两者合并为“记录推算资金变化”时同时显示拆分公式。

## 分阶段交付

### A. 数据与保护内核（已实现，待 iPhone 实机验收）

- 状态 schema v2 幂等迁移；保留旧 `records[]` 原值；旧版加密备份可读取，新字段在首次写入后进入新密文快照。IndexedDB 存储仍兼容现有 v1 object stores。
- 建立单注投注录入与结算编辑；投注/结算/旧版流水不互相重复计账。
- 预算设置页：月/周、周期预算、亏损上限、最大单笔、可选每日允许记账时段；默认不设金额、不限制时段，不替用户填数。设置后本周期只能降低额度或收紧时段，放宽延后到下一周期生效。
- 达到硬上限时禁止本工具新增投注记录，提供停止本周期、24 小时/7 天冷静期；只能由下周期自然解锁，允许用户降低上限。
- 提醒规则先透明、确定、可解释，并标为行为信号而非诊断：预算用量 80%/100%；亏损上限接近/达到；亏损后 24 小时内单笔增加超过 50%；滚动 60 分钟内 5 笔及以上；一周内 0–5 点至少 3 笔；亏损后 6 小时内新增存款。页面展示触发原因；部分提醒还需继续补齐具体记录的时间和可见引用。
- 风险提醒页使用尊重、不羞辱文案；显示“本工具只能约束本工具内的记录，不能阻止你在外部平台下注”，提供暂停、冷静期及平台限额/暂停/自我排除入口说明；不显示下一注或追回建议。
- 已完成代码：老账本字段保留并分离新口径；单注状态与 ROI；预算/亏损/单笔/允许时段拦截；停止/冷静期；行为提醒；最多 500 条修改历史；备份结构校验。已做语法与静态结构检查，尚未在 iPhone 15 验证实际交互、Safari 文件 API 与完整计算。
- 设备验收：使用虚构数据手算 open/settled/void 资金与 ROI；确认预算拦截只阻止新增投注、不阻碍纠错；确认冷静期自动结束；错误口令/损坏备份不会写入；确认旧版密文备份可在空浏览器导入。

### B. 记录与可审计分析

- 搜索、筛选、最近使用项及可编辑默认值；重复提示基于时间、平台、事件、金额，不强行删除相似记录。
- 补齐平均/最大投注额、连赢连输描述、分类级字段完整度；目前已交付整体所选字段完整度、类别覆盖时间跨度、样本数、ROI 和类别明细钻取。
- 小样本标签、数据完整度和时间跨度说明；胜负连串只描述历史，不作预测。
- 明文 CSV 导出需二次确认、清楚提示隐私风险；对以 `=`, `+`, `-`, `@`, tab 或回车开头的文本字段做电子表格公式注入防护，并提供 UTF-8 BOM；密文备份保留为首选。
- 修订历史可以查看；删除以 tombstone 记录，而非悄悄抹掉审计线索。

### C. 快速录入与图片识别

- 先完善手动表单、最近选项、可修改默认值、字段校验与重复确认。
- 图片仅在用户确认后选择，压缩到本机合理尺寸并与账本一起加密；允许查看和永久删除。图片文件不发到服务端，不请求体育投注账号口令。
- OCR 必须纯设备本地运行且无第三方上传；识别结果先进入待确认表单，金额、赔率、玩法、结果逐项突出确认，来源显示“图片识别”。不满足目标 iOS 离线/隐私要求时保留手动录入，不接云 OCR。
- 单独测算模型体积、内存、耗电和 iPhone Safari 支持后再选 OCR 实现；OCR 作为可选辅助，不影响手动记账。

帮助入口应常驻可见；先提供停止/自我排除等平台设置说明。真实支持机构按用户所在地区核实后再链接，不猜测地区或展示未经确认的电话号码。

## 设备与上线验收

每阶段先检查 JavaScript 语法、迁移路径、备份读写和明确公式；再用虚构数据走桌面浏览器操作；最后在 iPhone Safari 与主屏幕模式验收窄屏、键盘、文件选择、离线更新和加密性能。安装升级不得要求清除网站数据。真实记录上线前应确认至少一份独立加密备份可成功导入。

## 当前不做

不提供赛果/赔率预测、推荐、自动投注、加注/追损方案、预测型综合盈利分数、云 OCR、多设备同步或投注平台账号接入。没有真实用户确认的数据源与业务定义时，不接入外部赛事数据。
