# 筹记 PWA V1 技术实施计划

## 已实现

- Windows 可开发的静态 PWA，不依赖 Node 包或远程 Mac/Xcode。
- 概览、逐注明细、历史分析、预算保护四页。
- 手工新增和结算逐注记录；按事件文字搜索、状态筛选、分析分组钻取；编辑/删除均写入本机审计历史。
- 周/月预算、亏损上限、单笔上限、允许记账时段、周期停止和 24 小时/7 天冷静期；预算按投注日期，亏损上限按结算日期并计入全部未结算本金。新增投注在上限、冷静期或时段限制下会被应用内拦截。编辑可以纠错或降低风险，但不能增加超过既有上限的单笔、周期本金或亏损风险占用。
- 解释性行为提醒覆盖预算/亏损额度、短时密集投注、深夜集中、亏损后提高单笔和亏损后短时存款；提醒不提供下注方向或追损建议。
- 历史分析支持本月、本周、自定义范围和全部记录，并可按投注日/结算日、运动类别、联赛、玩法、赔率区间、平台、时段和星期查看；低于 30 笔已结算样本提示数据不足。
- 分析显示平均/最大已结算投注额、赢输笔数、最长连赢/连输、按本金区间分布、整体与分类字段填写率、类别覆盖日期范围。
- 修改历史可展开逐字段前后值；创建与删除事件保留对应记录详情，最多保留 500 条并在本机加密。
- 明文 CSV 导出须再次确认，使用 UTF-8 BOM，并对文本字段进行电子表格公式注入防护；加密 JSON 备份仍为首选。
- 旧版投注、派彩、退款流水保持原样，不自动映射为已结算投注；资金存取和独立退款仍使用现有流水结构，避免建立重复流水表。
- IndexedDB 本机账本使用 AES-256-GCM 加密；PBKDF2-SHA256 600,000 轮派生密钥；最多 5 份加密快照。
- 密文 JSON 备份可导出/导入；导入先解密验证主状态与快照，只允许在无账本的浏览器写入。
- 离开前台后锁定，静态资源离线缓存，存储配额状态提示。
- GitHub Pages 工作流仅发布运行时页面、脚本、样式和图标。

## 目标设备安装与验收

1. 在 iPhone 15 的 Safari 打开 Pages HTTPS 地址，使用“分享 → 添加到主屏幕”。
2. 先用临时口令与虚构数据检查创建、重开解锁、编辑、删除、恢复上一份快照。
3. 检查概览预算/ROI/未结算敞口/资金变化、逐注新增与结算、旧账保留、筛选钻取、预算拦截、冷静期、提醒和修改历史。
4. 导出加密文件；在空浏览器来源用原账本密码导入，核对流水数量和汇总；再用错误密码确认没有创建账本。
5. 验证离线冷启动、安装图标、安全区、数字键盘、弹窗、后台锁定和低存储提示。
6. 通过 GitHub Actions 确认 Pages 部署成功，并从 iPhone 实际访问更新后的版本。

浏览器使用 Service Worker，部署后会因缓存版本递增更新；若主屏幕旧版本未更新，可完全关闭后再打开，或先用 Safari 访问一次 HTTPS 地址。不要为强制刷新而清除网站数据，因为那会删除本机账本。

## 已知边界与风险

| 风险/缺口 | 当前处置 | 后续验证或改进 |
|---|---|---|
| 公开 Pages | 仓库只含应用代码与静态资源；记录不上传 | 不提交账本、备份或密钥；确认用户能接受公开程序 |
| 忘记账本口令 | 不保存口令，不存在服务端重置 | 使用强且可管理的独立口令，并保存离线副本 |
| PWA 身份验证与原生隔离较弱 | 账本口令解锁，切后台时锁定 | 不宣称等同 Keychain/Face ID；iOS 浏览器策略需实测 |
| PBKDF2 开销及全状态加密 | 当前适合轻量个人账本 | iPhone 15 上测首次解锁、保存耗时；大量记录时再做分块/SQLite 评估 |
| Safari 文件 API 差异 | 使用 JSON File API 与浏览器下载/选择 | 必须用目标 iOS 版本验证导出、导入和离线启动 |
| 浏览器存储被清理或设备损坏 | 页面提示 + 最多 5 份本机快照 + 密文文件导出 | 在 iPhone 验证文件可保存到“文件”并能重新选择导入 |
| 保护锁无法限制外部投注平台 | 达到预设上限后只拦截应用内新增记录，并提供停止/冷静期 | 实机确认保护页和平台限额/自我排除提示容易找到 |
| 自动行为信号可能漏报或误报 | 规则透明展示为提醒，不作诊断；保留记录纠错能力，但超限增量会被拦截 | 继续观察误报边界，不增加预测或盈利判断 |
| 分析仅描述本机手工录入 | 支持类别/日期维度、ROI、小样本提示、投注金额分布、字段填写率和赢输连串描述 | 检查不同筛选条件下的显示与样本边界；结果仍仅用于历史复盘 |
| 明文 CSV 会暴露隐私 | 导出前确认、公式注入防护、UTF-8 BOM；加密备份仍首选 | 在 iPhone 验证文件保存体验；导出文件需由用户自行安全保存 |
| 图片识别和附件尚未实现 | 当前只提供手工录入，不上传图片 | 先确认 iPhone Safari 可纯本机识别的 OCR 可行性，再决定实现 |

## 后续迭代建议

1. 将本版本部署到 Pages 后，用 iPhone 15 Safari 和主屏幕模式走完逐注、预算、冷静期、备份和更新路径；不清除网站数据。
2. 继续以虚构数据检查分类筛选、逐字段修改历史和不同屏宽下的金额分布展示；现有赢输与最长连串仅用于历史描述。
3. 评估纯本机图片 OCR 与加密附件前，先验证 iPhone 15 的性能和隐私边界；不接云 OCR。
4. 若出现多设备需求，先设计端到端加密同步和密钥恢复，再考虑服务端；当前没有云同步。
